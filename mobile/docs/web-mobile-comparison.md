# مقارنة تجربة LinguaBridge: الويب وتطبيق Expo

يحافظ التطبيقان على هوية واحدة وتدفق واحد: اختيار اللغة والموافقة في الردهة، ثم النص والترجمة داخل الغرفة، ثم المحضر والإعدادات. كلاهما يستهلك حزمة `@linguabridge/contracts` للغات وحالات الجلسة ومبادئ الخصوصية.

| المجال | الويب / PWA | تطبيق Expo الأصلي |
| --- | --- | --- |
| العرض والتخطيط | React وCSS متجاوبان على المتصفح | React Native ومناطق أمان iOS/Android |
| الميكروفون | `getUserMedia` وWeb Speech حيث يدعمه المتصفح | `expo-audio` لصلاحية الجهاز والتقاط الصوت المحلي |
| القراءة الصوتية | `speechSynthesis` في المتصفح | واجهة صوت النظام تُربط في مرحلة TTS الأصلية |
| المحاضر والتفضيلات | مربوطة بخدمات tRPC وقاعدة بيانات الويب | واجهات أصلية جاهزة للربط؛ تظل محلية إلى أن يتاح عنوان API منشور |
| الاتصال الجماعي | واجهة وخدمات بيانات جاهزة، دون WebRTC إنتاجي | واجهة وحالة محلية جاهزة، دون SFU/إشارات إنتاجية |

> تم اختبار معاينة Expo Web والمسارات الرئيسة. يلزم تشغيل المشروع على Expo Go أو جهاز iOS/Android فعلي لاختبار مطالبة صلاحية الميكروفون وسلوك الصوت الأصلي.
