# خطة قناة الإشارات والإعلامات للإنتاج

## الحالة الحالية

يعمل LinguaBridge حاليًا في **وضع بلا تكلفة**. لا توجد قناة إشارات دائمة، ولا خادم TURN أو SFU، ولا عامل دائم، ولا خدمة نسخ أو ترجمة صوتية مدفوعة مفعّلة. تدفق الويب والجوال الحالي مخصص لإنشاء الاجتماع والانضمام إليه وإدارة الموافقة والبيانات الموثقة فقط.

> هذه الوثيقة خطة هندسية مستقبلية، وليست إعلانًا عن تفعيل اتصال صوتي متعدد المشاركين أو بنية تشغيلية دائمة.

## فصل المسؤوليات

| المجال | المسؤولية المستقبلية | الحد الأدنى من البيانات |
|---|---|---|
| قناة الإشارات | تبادل عروض SDP ومرشحي ICE وحالات الانضمام والمغادرة | معرّف الغرفة، معرّف مشارك قصير العمر، نوع الحدث، وقت الحدث |
| طبقة الوسائط | نقل الصوت عبر WebRTC بين أطراف مخولين أو عبر SFU مُدار | رموز وصول قصيرة العمر؛ لا تُرسل النصوص أو المحاضر في قناة الوسائط |
| الإعلامات | تنبيه المستخدمين إلى الدعوات أو تغيّر الحالة | معرّف المستخدم والحدث فقط، مع رابط آمن عند الحاجة |
| المحاضر والنصوص | تخزين أو عرض المحتوى بعد الموافقة الصريحة | محتوى موثق، سجل موافقة، ضوابط العضوية والحذف |

## عقد الأحداث المقترح

لا يجوز تمرير المحتوى الصوتي أو النصوص المترجمة داخل أحداث الإشارات. ينبغي أن يلتزم كل حدث بالحقول التالية فقط:

```ts
type SignalingEvent = {
  roomId: string;
  senderId: string;
  type: "join" | "leave" | "offer" | "answer" | "ice-candidate" | "presence";
  issuedAt: number;
  payload?: Record<string, unknown>;
};
```

يجب رفض الأحداث عند تجاوز مدة الرمز، أو عدم تطابق الغرفة، أو غياب العضوية النشطة، أو زيادة المعدل المسموح به. ولا يحتفظ الخادم بحمولة العرض أو مرشحي ICE إلا بقدر زمن تمرير الإشارات اللازم.

## ضوابط الأمان والخصوصية

ينبغي إصدار رموز الغرف من الخادم فقط بعد التحقق من عضوية الاجتماع والموافقة المطلوبة. تُقيَّد الرموز بغرفة ومستخدم ومدى زمني قصير، وتلغى عند إنهاء الاجتماع أو مغادرة المستخدم. كما يجب تطبيق حدود معدّل للأحداث، وقائمة سماح للأصول، وسجل تشغيلي مجرد من محتوى المحادثة أو الصوت، ومسار واضح للإبلاغ عن خطأ الاتصال دون كشف بيانات الحاضرين الآخرين.

| الخطر | الضابط المقترح |
|---|---|
| دخول غير مصرح به للغرفة | رموز قصيرة العمر مرتبطة بالمشارك والتحقق الخادمي من العضوية |
| إعادة استخدام الرمز | انتهاء سريع، معرّف جلسة، وإبطال عند المغادرة أو الإنهاء |
| تسريب محتوى في السجل | منع تسجيل SDP والنصوص والصوت؛ حفظ مقاييس تقنية مختصرة فقط |
| إساءة استخدام الإشارات | حدود معدّل، حجم أقصى للحمولة، وإغلاق الاتصال عند مخالفات متكررة |
| اختراق الموافقة | إبقاء حفظ النصوص أو إنشاء المحضر مشروطًا بموافقة المشاركين كما هو في الخادم |

## مراحل التفعيل اللاحقة

| المرحلة | النطاق | شرط البدء |
|---|---|---|
| 1. اختبار محدود | قناة إشارات مؤقتة وتجارب اتصال ثنائي داخل بيئة اختبار | موافقة صريحة واختبارات أجهزة وشبكات حقيقية |
| 2. وسائط مُدارة | SFU وTURN بمفاتيح خادمية ومراقبة أعطال | ميزانية وتشغيل دائم وسياسة احتفاظ تشغيلية |
| 3. تعدد المشاركين | غرف متعددة ومؤشرات جودة وخطط استرداد | مراجعة أمان وتحمل وتحميل قبل الإتاحة العامة |
| 4. النسخ الحي | توصيل خدمة نسخ وترجمة اختيارية مع موافقة واضحة | موافقة صريحة على التكلفة ومزود الخدمة والاحتفاظ بالبيانات |

## قرار التشغيل الحالي

لا تُنفَّذ أي مرحلة من هذه المراحل تلقائيًا. يتطلب تفعيل TURN أو SFU أو خدمة نسخ حي أو عامل دائم موافقة صريحة لاحقة من مالك المشروع على نطاق التشغيل والتكلفة والخصوصية. وحتى ذلك الحين تبقى واجهات الاجتماع والرموز الخادمية الحالية ضمن حدودها التجريبية والآمنة.
